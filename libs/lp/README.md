# `libs/lp` — линейное программирование, двойственный симплекс-метод

Переиспользуемый модуль: решает задачи линейного программирования собственной
реализацией двойственного симплекс-метода. Сторонние решатели
(`scipy.optimize.linprog`, HiGHS, PuLP, OR-Tools, cvxpy) не используются ни в
коде, ни в тестах. NumPy нужен только как линейная алгебра — массивы и
`numpy.linalg.solve` для базисной матрицы.

Пакет ничего не знает о калькуляторе, `core/`, `features/`, FastAPI и
SQLAlchemy; это проверяет контракт `libs-are-pure` в `.importlinter`.

## Постановка

    min cᵀx  при  A_ub·x ≤ b_ub,  A_eq·x = b_eq,  lower ≤ x ≤ upper

Границы переменных могут быть бесконечными, в том числе двусторонне
(свободная переменная) и совпадающими (`lower[i] == upper[i]` — фиксированная
переменная). Строки «≥» принимаются как `a_lb·x ≥ b_lb` и приводятся к «≤»
умножением на −1.

## API

```python
from libs.lp import make_problem, solve

problem = make_problem(
    [1.0, 2.0],  # c
    a_ub=[[-1.0, -1.0]],  # A_ub
    b_ub=[-3.0],  # b_ub
    upper=[5.0, 5.0],  # по умолчанию lower = 0, upper = +inf
)
result = solve(problem)
result.status  # LpStatus.OPTIMAL
result.x  # план
result.objective  # значение цели
```

`make_problem(cost, *, a_ub, b_ub, a_eq, b_eq, a_lb, b_lb, lower, upper)`
собирает и проверяет задачу: размеры, конечность чисел, `lower ≤ upper`. При
ошибке — `LpProblemError`.

`solve(problem, *, warm_basis=None, tol=1e-9, max_iter=None, big_bound=1e9)`
возвращает `LpResult`:

| Поле | Что это |
| --- | --- |
| `status` | `optimal`, `infeasible`, `unbounded`, `iteration_limit` |
| `x` | план по структурным переменным (`None`, кроме `optimal`) |
| `objective` | `cᵀx` |
| `duals` | двойственные оценки строк |
| `basis` | базис для тёплого старта |
| `iterations` | число итераций |
| `residual` | наибольшая из невязок ‖A·x − b‖∞ и нарушений границ |

Тёплый старт: `solve(changed_problem, warm_basis=previous.basis)` — прежний
базис остаётся двойственно допустимым после изменения правых частей и границ,
поэтому повторное решение короче. Число переменных и строк при этом меняться
не должно, иначе базис отвергается с `ValueError`.

`to_standard_form(problem, *, big_bound)` и `StandardForm` доступны отдельно,
если нужен доступ к рабочей форме (дополнительные переменные, базис).

## Как это работает

- `problem.py` — постановка и проверка входа, приведение «≥» к «≤».
- `standard_form.py` — дополнительные переменные: slack `[0, +inf)` для строк
  «≤», фиксированные `[0, 0]` для равенств. Стартовый базис — из них, поэтому
  он сразу двойственно допустим и фаза I не нужна. Бесконечные границы
  переменных заменяются «большим ящиком» ±`big_bound`.
- `basis.py` — обратная базисная матрица, обновление в произведённой форме,
  периодическое повторное разложение и оценка накопленной ошибки.
- `dual_simplex.py` — итерация: выводимая переменная по наибольшему нарушению
  границы, двойственный тест отношений с переходом небазисных переменных между
  границами (bound flipping) и допуском Харриса, правило Бленда после серии
  вырожденных шагов.
- `result.py` — статусы и результат.

## Ограничения

- Плотные матрицы NumPy; разрежённость не используется. Модуль рассчитан на
  задачи порядка сотен переменных и строк (размер задач калькулятора), не на
  промышленные.
- Бесконечные границы заменяются конечными ±`big_bound` (10⁹ по умолчанию).
  Если оптимум опирается на эту искусственную границу, возвращается
  `unbounded` — то есть неограниченность обнаруживается, но задачи с законным
  оптимумом за пределами `big_bound` решать нельзя; в таком случае границу
  задают явно.
- Целочисленных переменных нет, задача только непрерывная.
- Цель всегда минимизируется: максимум получают сменой знака `c`.
- `iteration_limit` — не ошибка данных, а исчерпанный лимит итераций
  (`max_iter`, по умолчанию зависит от размера задачи).

## Тесты

- `tests/test_lp_dual_simplex.py` — учебные задачи с известным ответом,
  равенства, свободные и фиксированные переменные, задача Била (зацикливание),
  Кли–Минти n = 3…6, вырожденные, недопустимые и неограниченные задачи, лимит
  итераций, тёплый старт, проверка входных данных, отсутствие сторонних
  решателей в исходниках пакета.
- `tests/test_lp_oracle.py` — 200 случайных малых задач против полного перебора
  вершин на `fractions.Fraction`: совпадение статуса и цели до 10⁻⁹.

```bash
python -m unittest tests.test_lp_dual_simplex tests.test_lp_oracle
```
